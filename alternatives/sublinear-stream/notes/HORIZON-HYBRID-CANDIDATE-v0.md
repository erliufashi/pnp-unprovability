# 下一候选：固定horizon的延迟切换与非空洞性审计（v0，未认证）

特化已降低工作表系数，但toy p=134时仍比原KV大。不要据此认定对较小任务也必须先付大表。一个可检验方向是先原生、达到固定阈值后才重建压缩状态。

## 候选构造

给已满足M15契约的reference π及精确kernel编译器κ，固定H（独立任务输入和hard witness）。直到总处理token≤H，保留原生KV/同一控制器，不分配压缩forest。下一个feed前的稳定token边界：

1. 保留current hidden/位置/采样/预算控制不动。
2. 对每头已有的H条内部KV，从κ.Init按原顺序Push重建；不要重跑神经层或采样器，不回读原输入/外部输出。
3. 验证各头count=H+seed，切换backend并释放原KV。
4. 以后按已证接口归纳处理。

重建应不消耗/重置RNG。只在全部head同步的边界切换，避免半层重建。未到阈值就EOS的run应从未创建巨大forest。prototype要懒初始化而非先建完整表再报末态。

## 可能证明的内容与不能偷换的部分

对固定π/H，原生前段与一次重建的峰值都是模型相关常数，此后是κ的O(log t)；故有机会得到全域精确且总体O_(π,H)(log n)的模拟。∀H∃B_H不等于同一小常数B同时适合所有H，H若随每次输入取n就不能称固定阈值log空间。

总horizon≤H的任务在数值工作布局上走原生路径，未必有同一墙钟：比较/元数据/程序code本身也计费。若κ需要巨大readonly表或离线编译，不能因“未分配mutable forest”就忽略物理资源。

可另推具体组件竞争条件：若选H以后压缩槽S(t)≤R_native(t)，迁移同时持有的cache组件峰值≤R(H)+S(H)，但重建scratch/readonly code/控制需另算；这不是自动2×整设备保证。可用小zero-key控制验证switch/resource逻辑，不挑它做人类baseline。

## 非空洞性问题

给有限人类任务horizon一个巨大profile常数，可能让一个渐近小空间类在所有该范围内都复用原生行为，而分离见证只出现在更大范围。这个形式命题可以真，但不能包装成标准P/NP或域内实际难题发现。

应区分：给定全域κ后的精确混合，与只到H正确而之后拒绝的截断模拟。后者只覆盖T(π)|H，不能冒称reference无界任务空间。

若用户想要有实际解释力的更强终止条件，需事先固定共同任务宇宙/输入范围、数值资源/代码预算和输入协议，说明witness在哪个范围；不能要求witness同时在已覆盖的π可解子集中（那会矛盾）。这些是待选择的新标准，不改旧T3。

## 下一批MVP

- 普通toy profiles多个小H跨prompt/生成三路比对，EOS前未触发、恰阈值与混合过程中都检查。
