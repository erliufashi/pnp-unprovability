# 操作前缀契约：mask标签不等于逐位稳定

状态：本批语义审计，待独立复核。以下结构反例不是某真实GPU softmax/200B产品的实测反例，也不改变原T3证书。

## 1. 三个概念不能混用

- 内容mask：未来位置的值被置为零/不参与数学公式。
- 跨shape操作prefix-stability：未来token追加后，过去位置的hidden/KV及数值计算图不被重新解释，过去word值保持。
- 明确增量reference：本来就规定每位置只计算一次，旧KV被冻结；它未必逐位等价于从头batch重算的另一种实现。

若把“因果”定义为第二项，稳定性是定义的一部分；不能再声称仅从第一项的mask就证明了它。

## 2. 一个精确的masked-reducer反例

用word code集合−4..4，a⊕b=clip(a+b,−4,4)。0在这个操作下是严格的左右单位元，但⊕不结合。

让全batch长度决定归约树：每次按floor(L/2)切成左右子树，递归至单叶。过去位置的有效叶（含seed）为[0,4,4,−4]，结果：

(0⊕4) ⊕ (4⊕−4) = 4。

追加两个未来位置，并将它们对旧行的贡献mask成0。全长变成6，树结果：

(0 ⊕ (4⊕4)) ⊕ (−4 ⊕ (0⊕0)) = 0。

没有泄露未来内容，改变的是全shape下的括号。故mask不足以保证旧word在未来长度上不变。数字是本小域的word code；不能将之冒称真实softmax/GPU必有同一输出差异。

## 3. 本批采用的足够增量契约

固定有限层数L、每层有限头数、有限hidden/query/key/value字母表及只读有限权重。定义一个具体策略π_inc：

1. prompt按token单遍到达；每个位置p处理一次。位置特征ρ(p)的计算需O(log(p+2))空间及多项式时间，无无限非均匀位置表。
2. 层ℓ的q/k/v由当前位置的前层hidden、ρ(p)及固定纯word程序生成。不能读取未计费的原prompt、过去hidden列表或外部答案。
3. 每头只追加不可变(k,v)。所有过去访问只通过已明确定义的kernel接口；score的额外时间/相对位置依赖必须已编码或另行证明。
4. kernel的精确在线模拟器是一个有明确S(t)、T(t)界的接口假设；原始reference核可读取完整KV。该条件式提升本身不依赖特定森林已证明，方向D6再代入M14。
5. 本位置各头输出经固定有限、纯、逐位置post-map/残差生成本层hidden。不同层/头处理中缓存计数可以暂时不同，必须计费而非假定全局同时更新。
6. 前向无内部随机调用。若最终采样随机，使用明确且每次有界的采样内核/同一随机位耦合，RNG状态计入内存。无限拒绝采样不能直接当每条路径多项式时间。
7. EOF前不向外输出答案；之后按指定EOS或多项式token预算D(n)停止。输出是只写的，新token反馈只通过当前token进入模型，不把外部输出日志当工作带。
8. 位置/输入/输出/停止计数O(log(n+D(n)+2))位。空/非法输入需有固定有限规则，或明确不在任务输入域。

## 4. 这不是全体LLM的无条件推广

该契约允许某些无界append-only历史，但增加增量、局部生成及特定数值核假设。它不自动包含T3全部固定context profile，也不自动覆盖从头batch重算、双向全序列模型、动态改旧key、任意GPU树、内部dropout或外部工具程序。

若baseline从π_batch换成π_inc，必须另证两者任务指标接近；本文没有用“模型名字相同”代替这项义务。

此外，数值功能及token预算不等于保持OOM/墙钟超时/API发生时刻。若这些属于可观察任务输出，须模拟参考守卫或另证。巨大模型规模常数仍不产生实用200B或实证人类覆盖。
