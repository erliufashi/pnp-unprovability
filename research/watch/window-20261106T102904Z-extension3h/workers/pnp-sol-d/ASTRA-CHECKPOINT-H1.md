## 结论（局部、条件性）

`D-GVC-BATCH-1` 的候选容量曲线不能不加条件地迁移为 Generate-and-Verify 的资源闭包定理。迁移成立的最小条件是：每个候选都支付统一的最坏情况验证成本，候选 wire 表示/解析成本按实际字节计费，批反馈与持久状态是唯一答案相关的跨轮接口，且所有可读日志/缓存/句柄均归入状态或通信预算。在这些条件下，批反馈只给出一个**信息容量上限**；总时间和空间还必须满足候选数与传输量的额外约束。

若任一条件删除，则存在严格反例：相同的 `(K,L)` 和相同的一 bit batch 反馈，可以在调用预算内完成，也可以因验证或序列化成本超预算；或可借助未计费的可读验证日志获得远超 batch 曲线的信息。因此，单以调用次数/批大小宣称能力保全是错误的。

## 资源闭包账本

对隐藏答案 `x`、K 轮、每轮最多 L 个显式候选、候选固定 wire 长度 m bits，定义：

- `V_i(j,x)`：第 i 轮第 j 个候选的验证时间（包括服务计算、拒绝/接受路径）；
- `S_i(j)`、`P_i(j)`：序列化/发送及接收/解析时间；
- `B_i`：本轮 batch 反馈、路由、恢复、状态迁移的固定开销；
- `Q_i`：峰值时活跃的本地状态、远端状态、候选 buffer、scratch 和可读日志；
- `W`：总时间预算，`M`：峰值空间预算，`U`：总 wire bits/字节预算。

对任一输入轨迹，闭包约束至少是：

`sum_i [sum_j (V_i(j,x)+S_i(j)+P_i(j)) + B_i] <= W`,

`sum_i,j wirebits(i,j) + feedback/state-migration bits <= U`, 且 `max_t live_memory(t) <= M`。

同时保留原 batch 信息上界 `recoverable <= min(N, 2^h F(K,L))`（若另有 h 个答案相关 binary observations）。但实际可执行的 L 必须满足上述资源不等式；因此可写成对可行轨迹集合 `T(W,M,U)` 的容量上界，而不是直接把任意 L 代入 F。候选 payload 若是固定 m-bit 显式编码，单纯传输就至少付 `m * (#candidates)` bits；流式传输可降低同时存活 buffer，却不能免除总传输和解析成本。

## 严格反例 1：统一 `(K,L)` 但验证成本导致闭包失败

取 K=1、L=2、N=3，batch verifier 对两个候选只返回一个 membership bit。令每个候选验证时间为 C，序列化/解析为 1，反馈为 1；总时间预算 `W=2C+3` 时，批模型的两候选轨迹可执行，容量按原曲线计算。现在保持完全相同的 K、L、反馈语义，但令第二候选的 verifier 在某些合法输入上耗时 `100C`（例如需要完整证明检查，而第一候选是快速拒绝）。若闭包按最坏情况预算且 `W=2C+3`，第二轨迹不可执行；把该轨迹仍视为预算可行会误判闭包；单轮 F 上界本身并未因此失效。若系统改成“达到 W 即中止”，中止事件本身必须算作额外可观察结果或失败状态，不能继续使用原一 bit 树模型。

更强的 reject/accept 不对称反例：verifier 对错误候选 O(1) 拒绝，对正确候选需检查长度 r 的证书并用 Θ(r) 时间。若算法容量分析只数候选而不把接受路径成本纳入，预算允许大量错误候选但不允许完成正确验证；这不是信息论 batch 曲线能修复的缺口。

## 严格反例 2：候选序列化改变可行批宽

取单轮 K=1，L=2，隐藏答案候选长度 m，wire 预算 U=m。信息模型仍允许提交两候选并收到一个 membership bit，但注意 `F(1,2)=2`，不是3。但显式固定宽度 ABI 要传 `2m` bits，故只有一个候选在 U 内可提交，该两候选轨迹不可执行；单轮容量 `F(1,1)=2` 恰与原上限相同，因此本例只反驳轨迹的同预算可执行性，不证明最优容量严格下降（还未计 framing、地址和错误重试）。将候选压缩为短码并不自动消除此反例：若编码是可逆且覆盖任意 m-bit 候选，最坏情况仍需 m bits；若依赖共享字典/句柄，则字典或解引用服务必须进入 Q/U/W，不能作为免费 oracle。

## 多轮隐状态的迁移边界

持久 q-bit 内部状态只在“不可被外部答案相关读取、且更新仅依赖已计费反馈”的条件下不增加额外信息因子。若远端服务保留完整 request log，下一轮可读该 log，则它是答案相关 observation；若每轮可读 w bits 的迁移消息，容量上界应把累计通信宽度并入 h（至多乘 `2^w_total`），而不是继续把 q 当作免费工作空间。多轮状态同时还产生写入、读取、恢复和峰值共存成本；这些成本可使信息容量上限不可达。

## Generate-and-Verify 何时可安全组合

可给出如下条件性不变式：若 (i) verifier 的每候选最坏时间 ≤ c_v、序列化/解析 ≤ c_s，(ii) 每候选 wire 长度 ≤ m，(iii) 状态/log 接口答案相关宽度已计入 h，(iv) 反馈树节点没有额外答案相关分支，(v) 总预算按最坏轨迹闭包，则实际候选数 `C` 必须满足 `C(c_v+c_s) + overhead <= W`、`Cm + state/feedback_bits <= U`，并且容量不超过 `min(N, 2^h F(K,L))`。这只是必要上界，不能保证达到；达到还需构造调度和证明所有轨迹满足闭包。
