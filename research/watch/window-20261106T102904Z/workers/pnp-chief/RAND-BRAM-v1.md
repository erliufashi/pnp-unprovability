# E-chief-RAND-BRAM-1：全扫描共同预算下的常数错误边界审计

分类：反算法/条件边界审计，待独立复核；不是新的完整 D/ND 分离，也不是现实覆盖证书。

## 1. 共同模型与未决点

输入是 n 个可读的 word，算法允许随机访问、重读、普通计算和 full scan；每次被审计的 pair-comparison 读两个输入word，成本至少1；随机带、PC、16w寄存器、可写数组、初始化和代码必须另行计费。目标是精确判断是否有两个相等元素。共同预算可取上一候选的 F(n)=32n+512；它足够容纳SUM等全扫描基础程序，但不自动给出随机碰撞算法或下界。

Argon H2 已核对的 BSSV03 §6.2 条件不是常数错误率1/3的直接下界：其错误门槛随 T/n 的系数进入，例如 ε≤(T/n)^(-γ(T/n)^2) 或另一 S/n 条件。对 T/n 为常数的 F=32n+512，不能把该门槛改写成“排除BPP(1/3)”。本报告不填补这个缺口，而审计一个常见随机算法族及其正向promise界。

## 2. 唯一碰撞的pair-sampling负控制

算法族 `PairSample(q)` 均匀随机选 q 个不同无序pair，若见相等则接受，否则拒绝；不使用预处理或隐藏答案oracle。构造输入 `U_n`：只有一对位置相等，其余 n−2个值互不相等且与该值不同。对该输入，恰有一个成功pair，共有 C(n,2) 个pair，因此

`Pr[accept] = q / C(n,2)`（q≤C(n,2)）。

在 F(n)=32n+512 且每个pair至少一单位成本时，`q≤F(n)`。当 n=256 时 F=8704、C=32640，成功率至多 272/1020≈0.26667<1/3；精确不等式从 n≥208 起成立（n=207 时 3F>C，n=208 时 3F<C，probe逐项核验）。所以“随机抽少量pair/随机hash抽样”不能给所有输入1/3保证；单一隐藏碰撞是负控制。

这不是对所有随机RAM算法的下界：算法可以利用算术/排序/索引/多轮结构，若预算或输入协议改变，需另证。负控制只阻止把该算法族误写成BPP算法。

## 3. 稠密promise下的正向界（不冒称worst-case）

若输入至少有 d 个相等无序pair，独立均匀pair采样q次（允许重复）未命中概率为 `(1-d/C)^q`；不放回采样更小，为 `C(C-d,q)/C(C,q)`。因此成功概率至少

`1 - (1-d/C)^q`。

若 d≥δC，则取 q≥ln(3)/(-ln(1−δ)) 即可达到至少2/3。这个正向结论只适用于预先声明的dense-collision promise；唯一碰撞的d=1不满足固定δ。将promise删掉或把δ事后按测试集挑选，不能称全输入能力。

## 4. 资源与解释边界

pair sampling的随机索引、采样去重、比较结果、终止/输出也应计入F；上述概率只对pair查询数给上界，未把Python模拟器内存/RNG当设备账本。允许可信duplicate summary、输入相关索引或Build后查询会改变协议，必须把预处理/索引状态计费；不能以本负控制否定这些不同模型。

本节点的有效增量是：把“BSSV强错误门槛缺口”与一个可精确计算的worst-case反算法分开；给出一个可接受的dense promise正界；明确尚未证明常数错误率full-scan BRAM的全类下界。T1/T2/T3-v2均保持UNRESOLVED。
